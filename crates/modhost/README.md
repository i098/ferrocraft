# crates/modhost

Owner: fc-modhost-pvp

Rust side of the mod host. It starts the JVM that `java/modhost` prepares, and talks to it over a loopback TCP socket.

- `ModHost::start` spawns Temurin 8 with LaunchWrapper, the Forge 1.8.9 `FMLTweaker` and `net.ferrocraft.tweak.HostTweaker`, and returns at once. A random token goes to the JVM in its environment (`FERROCRAFT_BRIDGE_TOKEN`); the JVM sends it with its hello, and a connection without it is closed. The JVM loads the mods from `GAME_DIR/mods`. A worker thread waits for its connection and stops, with a log line, if the process exits first.
- The worker then runs one frame per `ModHost::set_view` call (one per engine draw): it sends the window size, GUI scale, whether a screen is open, the mouse and the key and mouse events since the last frame (each marked with whether a screen was open when it arrived), and reads back whether a screen a mod opened is current, then the draw commands: filled rectangles, gradients, text, images and clip rectangles from the mods' `Gui`, `FontRenderer` and OneConfig renderer calls. Image files (PNG or SVG) come once, by name, and are kept. When the JVM closes the socket the commands are cleared and the mod screen flag is reset.
- `ModHost::draw` draws the last frame into the engine's `Gui`, over the HUD, only where the HUD is shown. It returns the PNG files of new textures (SVG files are rasterized with resvg at the pixel size they are drawn, rounded up to a multiple of 16, and in white when the call recolors them: the tint gives the color) for `Renderer::register_texture`. `ModHost::screen_open` is the mod screen flag: the engine treats it as an open screen in a world, frees the cursor, and keeps key and mouse events from the game and from its own menus (they go to the JVM only).
- `ModHost::window_event` queues key, mouse button and wheel events from winit, in order, from the start of the JVM: events that arrive before the JVM says hello are sent with its first frame, so a key pressed while the mods load is not lost. `keys::lwjgl` maps a winit key to its LWJGL 2 key code. A key press also carries the first character of the winit key text (0 when none, or when it is outside the BMP); `Keyboard.getEventCharacter` returns it, so a mod screen can type into a text field.
- `ModHost::player_tick` sends the player state (on ground, food, flight, item use) once per game tick (wire message `P`) and waits up to 100 ms for the sprint and sneak state that the mods leave after the stand-in `EntityPlayerSP.onLivingUpdate`. When the JVM does not answer in time it returns `None`, the engine uses its own input, and no more ticks are asked until the pump has finished its round trip; the late answer is dropped.
- `ModHost::set_mirror` queues the HUD state (FPS, ping, position, facing, biome, health, held slot, inventory with armor, effects, server address; `mirror.rs`, wire message `M`). The worker sends the newest one before the next frame, once.

The wire format is in `wire.rs` and in `java/modhost/src/net/ferrocraft/host/Sink.java` (commands) and `Host.java` (frames).
